# 训推不一致与“两个实现结果不同”：文献调研（2026-11-25）

**动机**：RL 训练框架与推理引擎对同一模型、同一 token 算出的概率不同（训推不一致）。我们想知道：
1. 别人做到了哪一步；
2. HPC 里有没有同类问题；
3. **（导师强调，最重要）一点点精度差距，是否真的会造成大影响**。见第4节。

**方法**：子代理检索并打开原文。主会话核实了标 ✔ 的条目，即打开过原文或源码。其余条目来自子代理的阅读，标“摘要”的只读了摘要。

## 1. RL 训推不一致：现象、修正、系统方案

### 1.1 测量与诊断

| 工作 | 测到了什么 | 归因 |
|---|---|---|
| Yao 等，TIS 博客（UCSD/Microsoft，2025-08） | vLLM 与 FSDP 的逐 token 概率差最大约 1.0；INT8 rollout 更大 | 后端、内核、并行方式不同；FP32 lm_head “有帮助但差距仍在” |
| Liu、Li 等，“When Speed Kills Stability”（ByteDance，2025-09-17） | `vllm-kl` 尖峰先于崩溃；集中在低概率 token、多轮工具调用 | A100 上关掉 cascade attention：KL 从约 3e-2–1e-1 降到 1e-3。FP32 lm_head 无效。硬件差异：H20 < L20 < A100 |
| MiniMax-M1（arXiv 2506.13585） | 训推 token 概率相关系数约 0.9x | 逐层分析：LM head 的大幅值激活是主要误差源；改 FP32 后达到 0.99x |
| Fireworks，MoE 训推一致（2026-03） | 融合 MLP 权重使 k3 从 7.0e-5 升到 1.93e-4；换成 HF 的 MoE 聚合后 k3 从 0.296 降到 0 | 单层单独测都干净，约 40 层后才出现漂移 |
| VeXact（arXiv 2605.14220） | 逐位一致的参照引擎；vLLM 重算的运行崩溃，VeXact 不崩 | 小的 token 级不一致本身就能导致崩溃；K1/K3 KL 估计器发现不了早期失败 |
| Du 等，TMLR 2026（arXiv 2609.26621，摘要） | BF16 与 FP16 的贪心输出在 49–100% 的提示上分叉 | 由 LM head 处最大两个 logit 的间隔决定 |
| Yuan 等（arXiv 2506.09501，摘要） | BF16 贪心解码的准确率随 GPU 数、型号、批大小最多变化 9% | — |

### 1.2 算法修正（把不一致当作已知，修正梯度）

- **TIS**：按 min(π_train/π_rollout, C) 加权。
- **MIS / Seq-MIS / Geo-RS**：Liu、Li，已进入 verl 的 Rollout Correction。
- **IcePop**：Ring-1T，arXiv 2510.18855。只保留概率比在 [0.5, 5] 内的 token，约屏蔽 1–2‰。给出不一致按复利增长的下界定理。
- **GSPO**（Qwen，2507.18071）：认为序列级似然能容忍不一致。
- **DeepSeek-V3.2**：off-policy 序列屏蔽、Keep Sampling Mask、Keep Routing。
- **Trust Region Masking**（2512.23075）、**DVP**（2512.23087）、**CIS**（2609.32444）、**Score Centering**（2609.20807）。
- **2610.40945**：把误差精确分解为“数值差异（近似常数）+ 策略滞后”。
- **2602.01826**：认为不一致是优化问题，随梯度噪声增长。
- **MoE**：R3（2510.11370，路由回放）；RDC（2610.21682，认为 R3 使梯度有偏）。

### 1.3 系统方案：让两边逐位一致

| 方案 | 保证 | 代价 |
|---|---|---|
| Thinking Machines 批不变内核（2025-09） | 与批大小无关；RL 中 KL ≡ 0 | Qwen3-8B 从 26 s 变为 42 s |
| vLLM + TorchTitan（2025-11-10） | 逐位一致；人工审计每个内核调用 | 慢 2.4 倍，只支持 eager |
| SGLang 确定性推理（2025-09） | 确定性；只支持稠密模型、TP1/2 | 平均慢 34% |
| slime/Miles “true on-policy” | 稠密模型 KL = 0 | “可接受”，没有数字 |
| TBIK（2511.17826） | 与 TP 大小无关 | 约为 cuBLAS 吞吐的 63% |
| vLLM/Inferact（2026-10-14） | DeepSeek-V4-Flash FP8 每步差为 0；基线 KL 从 2e-3 增长到 29.9 | 吞吐为基线的 91.3% |
| Detent（2611.10611，摘要） | 批不变 | 延迟为原来的 1.04–1.17 倍 |
| IsoExec（SkyRL）、Google TPU、AMD RL-Kernel | 逐位为零 | 25%（IsoExec） |
| FP16 替代 BF16（2510.26788） | 不一致约小 24 倍 | 几乎无代价；论证是定性的（尾数 7 位对 10 位） |

### 1.4 算子层面：哪里不一样（来自 issue 和博客）

| 来源 | 数字 |
|---|---|
| **MoE 路由翻转** | 每步 0–2 个 token 偏 10.8–31 nats（NeMo-RL #4459）；MoE 的 k3 为 1e-3–1e-1，稠密模型为 1e-5–1e-3（Miles） |
| **attention 后端**（FA2/FA3、cascade、split-KV、tile 切换） | 每层 93–96% 的元素相等；端到端 304 个 token 中 240 个不同（verl-omni #637） |
| **RMSNorm、残差融合顺序** | 74% 的元素相等（verl-omni #637）；启动配置改变归约顺序，导致 1.5–3% 的 argmax 翻转（vLLM #48271） |
| **RoPE** | 73% 的元素相等 |
| **采样语义** | top-p 重归一化引入 log(S) 偏移；处理后与原始 logprob 不同（TRL #6789、vLLM RFC #42259） |
| **真正的 bug** | vLLM Mamba-1 kernel 的 uint32 溢出，step 0 平均 logprob 差 0.11（AI21，已修复）；前缀缓存跨权重更新（ServiceNow） |
| **逐位相等的部分** | GEMM、fp32 log_softmax（verl-omni #637 的受控实验） |

### 1.5 工具

- **对比工具**：SGLang dumper/comparator、Megatron-Bridge compare.py、PyTorch DebugMode、HF debugger。阈值都是人工设定的。
- **OpGuard**（OSDI '26）：在异构训练栈之间找第一个不一致的算子，目标是训练栈，不是训推对比。
- **vLLM/Inferact 的 11 道关卡 agent skill**：工作流，不是工具。
- **有舍入意识的容差**：只有 numoracle 和 `torch._dynamo.same`，而且都是对照参考结果，不是训练和推理两边互相对照。

### 1.6 最接近我们设想的工作 ✔

- **Wu、Xu，“Behavioral Consistency in Machine Learning”**（arXiv 2606.07581 v2，2026-10-21，原题 “Training-Inference Kernel Contracts”；UC Berkeley 与 Stanford）✔
  - 给内核对立“契约”：数值、统计、运行时、可观测四类条款，外加升级策略。
  - 引理1：TV ≤ ‖ε‖∞/(2T)，KL ≤ ‖ε‖∞²/(2T²)。
  - **引理2：logit 误差的跨度 < 最大两个 logit 的间隔 ⇒ 贪心 token 相同**。
  - **但 ε 是对照参考内核实测的，不是从精度方案推出的**；证明在纸面上。
  - 实验只比较推理内核之间（Qwen2.5-7B，500 个提示，只看第一个 token）；作者自己说没测过对完整 PPO/GRPO 的影响。
- **DVP 命题4.2** ✔：|Δlog p_a| ≤ 2ε_max(1−p_a)。**ε_max 是假设的常数**，既没测，也没从浮点精度推出。另外，证明里的 p_a 取在中间点，与命题陈述不完全一致。
- **MarginGate、Vega-Fafnir**：按间隔决定是否重算，阈值是经验标定的。
- **Vosti**（2609.38981，摘要）：用 Verus 证明单个推理引擎内逐位确定，不涉及误差界或训推对比。

### 1.7 还空着的（截至 2026-11-25）

1. **从内核精度方案（累加格式、split-K、归约次序、FP8 块缩放）事先推出 ε，并做机器证明**，用于训练内核与推理内核这一对。
   - 已有的 ε 要么实测（Wu–Xu），要么假设（DVP），要么取逐位一致（所有系统方案）。
2. **系统的逐算子归因表**：每个算子对 logprob/KL 的贡献各占多少。只有单旋钮消融和定性清单。
3. **自动化的训推逐算子比较 + 证书工具**：现有的是人工或 agent 工作流，阈值人为设定。

## 2. HPC 中的同类问题：两个实现、移植、编译器、精度的结果不同

### 2.1 气候与天气：唯一有制度化统计检验的领域

- **CESM-ECT / UF-ECT**（Baker 等 2015；Milroy 等 2018；Price-Broncucia 等 2025）
  - 做法：在初始温度上加 1e-14 的扰动，生成集合，做 PCA 打分，看新构建能否来自同一分布。阈值按 0.5% 的误报率标定。
  - 抓到的真 bug：Mira 上只在大端机器出现的云生成器 bug；CICE5 的错误。
  - **局限**：
    - 开启 FMA 后结果统计上可区分，但机理不明，也判断不了哪个是对的；
    - 测不了降精度（FP32 会吞掉 1e-14 量级的扰动）；
    - 年均值漏掉小尺度 bug；
    - 不能定位，需要 KGen、FLiT 等另外的工具。
  - **MPAS-A 的一个 off-by-one bug**：与正确重构的 RMS 差几乎一样（0.12436 对 0.12430），但 UF-ECT 100% 抓到。
- **E3SM**：多元检验（energy、MMD、KS），带功效分析（Mahajan 2019）。
- **EC-Earth3**（Massonnet 2020）：换机器后 13 个指标中 4 个被拒绝，疑似未初始化的数组。结论：“默认应假设地球系统模型在换环境后不可复现，除非证明相反。”
- **COSMO**（Zeman–Schär 2022）：GPU 与 CPU 不可区分；单精度版本被拒绝。
- **IFS 单精度**（Váňa 2017）：按预报技巧接受，需要质量修正；FP32 暴露了 FP64 下也存在的薄弱环节。

### 2.2 其他领域

- **分子动力学**：
  - AMBER SPFP 用 64 位定点累加，结果与 GPU 数无关，按能量漂移接受（Le Grand 2013）；
  - GROMACS 每次发布都要通过统计物理检验（Merz–Shirts 2018），并发现 Berendsen 恒温器偏离 46σ；
  - 轨迹本身是混沌的，只要求统计量可复现。
- **CFD**：
  - MFC 的 500 多个回归测试用 1e-12 的容差，找到至少 15 个编译器和系统 bug；
  - AMReX、ERF 用 1e-12 的金标准文件。
- **格点 QCD**：混合精度求解器靠“reliable updates”，用高精度真实残差做后验检查。不比较两个实现，靠构造保证可接受。这与我们的接受门同理。
- **N 体**（Portegies Zwart 2014）：单条低精度解是错的，但能量误差 < 1/10 时，集合分布不可区分（作者称这是猜想）。
- **编译器**：
  - FLiT（Bentley 等 HPDC 2019）：Laghos 在 xlc -O3 下能量变化 11.2%、密度变负，根因是 `== 0.0` 的分支翻转；
  - MFEM 在温和优化下出现 180% 的误差。
- **code_aster**（Févotte 2017）：Verrou 随机舍入发现 72 个测试中 3 个不稳定，定位到稀疏点积，改用补偿点积修复。

### 2.3 用证明过的误差界判一致性：只在内核和线性代数层

- **HPL-MxP**：后向误差 ≤ 16 才有效；2025-06 起禁用 16 位以下精度，理由是“没有理论分析”。
- **FP64 仿真**：Brower 等（2611.19008）证明 Ozaki-II 保持经典点积界；Demmel 等按误差界给 BLAS 评级。
- **Zhang（2611.31030，未经评审）**：每个仿真乘积都满足 B 级界，但分块三角求逆的误差是 7.1e-2，原生 FP64 是 2.0e-15。**逐内核的界不能自动组合成整个例程的精度**。
- 气候、分子动力学、CFD 应用中**没有**用证明过的界判一致性：混沌使轨迹级的界失去意义，所以这些领域用统计。

### 2.4 对我们的含义

- 迭代精化的接受门，就是 HPC 里“用高精度真实残差做后验检查”这一传统（格点 QCD 的 reliable updates、HPL-MxP 的检查）的机器证明版本。
- 跨实现一致性在 HPC 里是**统计**问题（气候），或**金标准容差**问题（CFD）。证明过的界只在不混沌、不迭代的内核上可用，而且不能自动组合。这正说明，界应该用在内核这一层，内核之上靠统计或后验检查。

## 4. 一点点精度差距是否真的造成大影响（导师的问题，最重点）

### 4.0 一句话结论

**要区分两种“差距”。**
1. **良性的舍入差**：比如归约次序不同、稠密模型的 BF16 批次差异。它会让逐字输出大量不同，但对平均分、对标准设置下的 RL 结果，**目前没有可靠证据表明有显著影响**。
2. **结构性的差异或 bug**：MoE 路由翻转、FP8/INT8 rollout、采样掩码不一致、logprob 语义不一致、一边 FP32 一边 BF16 的“精度契约”不同，以及真正的内核 bug。这一类**被多个团队反复证明会导致退化或崩溃**。

很多“训推不一致毁掉 RL”的结论，实际混入了第二类。

**另外，决定后果的是舍入发生在哪里，而不是平均误差大小。** Ke 等 2610.32951 ✔：只把 RoPE 路径的舍入位置对齐，平均 KL 只降了 3–22%，却防止了崩溃。

### 4.1 RL 训练：因果证据（只改数值、其他不变）

**支持“有影响”的**（大多单种子）：

| 工作 | 干预 | 结果 | 种子 |
|---|---|---|---|
| VeXact（2605.14220） | 逐位一致的 rollout 与 vLLM 比较 | Qwen3-1.7B：vLLM 约 1665 步后崩溃到 0，VeXact 稳定在约 0.93；Qwen3-30B-A3B：验证奖励 0.067 对 0.534 | 1.7B 跑了3个种子，但只给定性结论；30B 单种子 |
| FP16（2510.26788） | BF16 改 FP16 | 原始 GRPO 在 BF16 下崩溃；最好的 BF16 修正达到 AIME24 34%，FP16 为 39% | 没报告种子 |
| Detent（2611.10611） | 训练端用推理内核，KL=0 | 基线 AIME24 从 29.2% 掉到 8.5%；Detent 稳定 | 单种子，训练端路径也变了 |
| R3（2510.11370） | MoE 路由回放 | GRPO 在第 60/105 步崩溃，R3 不崩 | 单次运行 |
| ScaleRL（2510.13786） | 两边 LM head 都用 FP32 | 渐近值从 0.52 升到 0.61（误差 ±0.02）；但在稠密 8B 的完整配方里“几乎没区别” | 3 次运行 |

**反面证据**（去掉不一致没有帮助，或有不一致也正常训练）：
- **slime/Miles** ✔：300 多次运行，“在稠密模型上，我们从未观察到因训推不一致而崩溃……即便开启 Truly On Policy，奖励也没有更好”。GLM-4.5 到 4.7 的生产训练从未崩溃；找了几百次才找到一个罕见的 MoE 崩溃案例。
- **Yichuan Wang + TorchTitan**：零不一致“没有带来明显的准确率提升”；批不变称为“调试工具，不是生产默认”；代价是训练吞吐慢 2–3 倍。
- **IsoExec**：35B-A3B 跑 50 步，“没有观察到有意义的奖励提升”。
- **Score Centering**（2609.20807）✔：“很难找到不一致严重到能看出统计显著差异的自然设置”，只能人为注入噪声。
- **CIS**（2609.32444）：唯一用 3 个种子测 FP16 的，在 3 个 MoE 模型上 FP16 与不做修正持平。
- **Beyond Precision**（2602.01826）：FP16 照样崩溃；把学习率从 1e-6 降到 1e-7 后，不一致和崩溃都消失。这说明不一致可能是优化病态的症状，而不是原因。
- **Yao 等自己的讲稿**：不一致小的时候，TIS“不一定有帮助”；在简单任务上“可能可以忽略”。

**剂量-反应**：
- 2611.11450 ✔：标准 BF16 引擎的不一致是 0.0008 nats/token；REINFORCE 在约 12 倍、GRPO 在约 60 倍时才出问题（200 步，单次运行）。**自然的 BF16 不一致比崩溃阈值低约一个数量级。**
- 2610.40945：FP8 sampler 约 0.02 nats/token，不修正时准确率从 46.5% 掉到 26.4%。
- 业界常用的“k3 < 1e-3 就安全”**是工程门槛，不是从结果推出来的**。而且基于均值的门槛看不到尾部：NeMo #4459 的平均 KL 只有 0.00082，但每步有 0–2 个 token 偏 10.8–31 nats。

**放大条件**：
- 证据强：MoE、FP8/INT8/FP4 rollout、低概率 token；
- 证据中等：长序列、多轮工具调用、学习率、过时程度（staleness）；
- 作用不清：模型规模。

**混杂因素**（报告中的“不一致”实际是别的东西）：
1. 内核 bug：cascade attention 的 FA2 split-KV LSE 错误（“Speed Kills”中 A100 的结果，部分可能是它）；Mamba uint32 溢出；RMSNorm 的块大小随 token 数变化；
2. 语义不一致：vLLM V1 默认返回原始 logprob；
3. 采样掩码：top-p/top-k 不一致，“全面失败”；
4. 精度契约不同：只有一边用 FP32 LM head；
5. 过时与策略滞后；
6. **权重导出的舍入** ✔（Gao & Gao，2610.41073，25 对匹配种子，目前最严谨的多种子结果）：BF16 就近舍入导出时，每步只有 0.4–0.5% 的权重真正改变，sampler 落后 50–150 步；可见的训推不一致始终约为 0.01/token，看不出这个滞后。改用随机舍入导出，平均提升 6.1 分。**FP16 的好处可能部分来自这里，而不是内核差异。**

**还不知道的**：
- 没有任何研究每组至少用 5 个种子，比较逐位一致与默认数值，所以效应相对种子方差有多大，没有被测量过；
- 自然量级舍入的受控剂量-反应不存在。

**最能定论的实验**（子代理建议）：
- 训练端和导出权重在各组间逐位相同，**只改 sampler**：(i) 逐位一致；(ii) 同样的内核，只在 sampler 上关掉批不变；(iii) 人为放大 3 倍、10 倍的扰动；
- 再交叉“是否做 IS 修正”和“稠密 vs MoE”；
- 每格至少 8 个种子，至少 1000 步；
- 比较 (ii) 和 (i)，就直接回答“良性的微小精度差异是否重要”。

### 4.2 LLM 推理与评测

- **逐字输出**：BF16 下推理模型在 90–100% 的提示上分叉（Yuan 等，NeurIPS 2025）。Qwen3-235B 在 T=0 跑 1000 次，得到 80 种不同的结果（Thinking Machines）。
- **平均分**：精度、批大小、负载改变，以及 FP8、W8A8、W4A16 量化，基本**不改变**平均分。
  - Yuan 的“最多 9%”是 12 种配置下的**标准差** ✔，AIME 只有 30 题，与单次运行的采样方差（约 6–9 个百分点）相当；
  - FP32 下 Qwen3-32B 的平均分与 BF16 几乎相同，只是波动范围更大。
- **单题对错**：1–19% 的题目翻转，而平均分不变。
  - Detent ✔：只改负载，790/1319 道题输出文本变了，但只有 33 道答案变了；
  - Du 等：Qwen2.5-3B GSM8K 上 19% 翻转，平均分只差 1 个百分点；HumanEval 上 token 级只有 26.2% 一致，但执行结果 97.6% 一致；
  - 量化的“flips”（Dutta 等，NeurIPS 2024）：准确率变化 0–2%，翻转可达 13.6%。
- **训练（非 RL）**：
  - **有偏的**舍入会真正破坏训练：BF16 FlashAttention 的舍入偏差导致 loss 爆炸（Qiu–Yao ICLR 2026）；纯 BF16 权重的更新被吞掉（Gopher、Collage）；FP8 累加只有 14 位（DeepSeek-V3，靠每 128 个元素提升一次精度来解决）。
  - **无偏的**归约次序噪声，效果相当于换随机种子（OLMo 2、Golden 等）。
- **还不知道的**：数值差异是否导致排行榜名次反转、对安全评测和 LLM 评审方差的独立贡献。

### 4.3 放大机制：定量链条

| 环节 | 最好的数字 | 状态 |
|---|---|---|
| 精度 u 到 logit 误差 | 稠密 BF16：‖ε‖∞ 平均约 0.26，约为 FP16 的 8 倍（与 u 之比相符）；MoE 每个 logit 的标准差约为稠密的 4 倍，尾部到 10 | 已测量；**理论界宽到无意义**（Budzinskiy 等的最坏界高估若干数量级） |
| logit 到贪心翻转 | 0.3–1.3% 的解码步翻转；翻转只发生在最大两个 logit 间隔 ≲ 0.25–0.375 的位置，这类位置占 4–11% | 已测量；翻转条件已有证明（Wu–Xu 引理2、Du 命题1） |
| logit 到采样翻转 | TV ≈ 0.01，共享种子时 1–2% 的 token 不同（稠密），MoE 2–5% | 已证明（耦合界）并测量 |
| 翻转到整段分叉 | 每个 token 的分叉概率近似恒定，P(前 n 个相同) ≈ (1−f)^n；BF16 平均 35–100 个 token 分叉 | 已测量 |
| 分叉到最终答案 | 1–19% 的题目对错翻转 | 已测量（样本小） |
| 进入 RL 比率与梯度偏差 | KL 约 1e-3/token；比率 p1–p99 在 [0.88, 1.13]；偏差约为梯度范数的 3%（Wu–Xu）；损伤集中在低概率 token（DVP 的 (1−p) 律，CIS 实测证实） | 已测量 + 证明 |
| RL 偏差到训练轨迹 | 崩溃与 KL 上升相关，但平均 KL 不是充分统计量（RoPE 结果） | **最弱的一环**：只有经验相关，IcePop 的定理把要证的增长当作了假设 |

**形式化能补的位置**：
- “精度 u 到 logit 误差”这一环的已发表界都没有意义，而下游所有已证明的引理都把 ε 当作已知输入。
- 一个**差分界**，即两种精度方案之间 logit 差的跨度，而不是各自对精确值的界，可以直接接进这条链。
- 这个界必须考虑舍入发生的位置（RoPE、SwiGLU、RMSNorm、logit 存储）和路由翻转条件。
- 但“偏差到崩溃”是动力学问题，光靠精度界补不上。

### 4.4 HPC 科学计算

**总体规律**：平台和舍入差异无处不在，经常改变**单个输出**：一个被试的分割、一棵基因树、一条轨迹。真正改变**科学结论**的有记录案例，可以归为两类：
- 结论本来就脆弱：p 值在 0.05 附近、似然函数很平、近似平局、估计不适定；
- 有潜伏的 bug，或者低精度累加有**系统性偏差**。

稳健的结论都扛住了，包括集合统计量、大效应，以及误差棒远大于舍入的量。

**改变了单个输出或伪结论的案例**：

| 领域 | 案例 | 数字 | 机制 |
|---|---|---|---|
| 神经影像 | Glatard 等 2015（只换 glibc 2.5 与 2.18） | FSL FIRST 只有 12.7%（286/2250）的分类完全一致，小结构的 Dice 低到 0.59；CIVET 在 p<0.05 下出现“显著”的组间差异，FreeSurfer 两个构建之间也出现显著簇 | 单精度 `expf` 等函数，加上 `floorf`/`ceilf` 改变了循环边界和控制流 |
| 神经影像 | Chatelain 等（bioRxiv 2026，预印本） | 21–31% 的区域×分析对 p 值越过 0.05 | 翻转集中在阈值附近 |
| 系统发育 | Shen 等 Nat. Commun. 2020 | 同一种子下，IQ-TREE 18.11%、RAxML-NG 9.34% 的基因树拓扑不同；3–5 线程时约 35.8%（逐位点 log 似然的求和顺序） | **不可复现的树更常是错的**（nRFD 0.485 对 0.147）：不稳定是可辨识性弱的症状 |
| 计量经济 | McCullough–Vinod AER 2003 ✔ | 五个软件包都“收敛”，系数从 4.4 到 8.1，标准误从 46 到 114,550；MLE 根本不存在 | 不适定、求解器选择，不只是末位舍入；有反驳（Shachar–Nalebuff 2004） |
| 有限元 | FLiT：Laghos（HPDC 2019） | -O3 改 -O2，能量从 129,664.9 变成 144,174.9（+11.2%），密度变负 | `== 0.0` 的分支翻转，开发者确认是 bug |
| 气候 | CESM 开启 AVX2/FMA | UF-CAM-ECT 失败率 92%（关闭时 2%），定位到 MG1 微物理 | 增长机理仍不明 |
| 气候 | EC-Earth 3.1 | 13 个指标中 4 个不同，南极海冰差异超过成员间范围的 2 倍 | 疑似未声明的数组（潜伏 bug） |

（Glatard、Shen 的数字来自子代理的阅读笔记，主会话没有核对原文；McCullough–Vinod 已对原文核实。）

**低精度的静默危害**（第 4 类，有偏累加）：
- **FESOM2.8 FP32**（2611.11248，摘要）：盐分持续流失，海洋热含量少了 129 ZJ，原因是“大的盐度值上加小增量被舍掉了”，也就是大数吃小数。改用 64 位累加后恢复，代价 ≤ 8%。
- **陆面热扩散**：FP32 下增量舍入为零而停滞（CLASS、Paxton 2022）；随机舍入或补偿求和可修复。
- **爱国者导弹**（GAO 1992）：0.1 在 24 位寄存器中被截断，100 小时后时钟偏 0.34 秒，距离门偏移约 687 米，28 人死亡。这是**系统性截断**，不是随机舍入。
- **未加保护的仿真**：cuEST 中 Ozaki-I 只用 1–2 个切片时误差极大；Zhang 2611.31030 中逐个乘积满足界，但组合后求逆误差为 7.1e-2，在一个 cokriging 应用里预测偏离被放大 120 到 33,000 倍。

**无害的案例**：
- IFS 自 2021-05 起业务上使用 FP32，只有平流层位势高度评分可能下降不到 1%；
- FP32 耦合簇的误差为 1e-5 到 1e-6 Eh，远小于化学精度 1.6e-3（积分与 HF/DFT 仍用 FP64）；
- 格点 QCD 的 reliable updates 恢复到完整双精度；
- 加了保护的 FP64 仿真：OpenMX + GEMMul8 的 |ΔE| ≤ 2e-12 Ha，SCF 迭代次数不变；
- ATLAS 在 x86 与 ARM 之间的差异为 1e-4 到 1e-6，远在蒙特卡洛统计误差内；
- CovidSim 的变化“大多低于 5%”，参数不确定性大得多。

**放大条件的分类**（每类给出最强的例子，并说明是否也出现在 LLM 中）：

| 条件 | HPC 例子 | LLM 中是否存在 |
|---|---|---|
| 混沌 | 三体问题；CESM FMA | 有：自回归分叉 |
| 阈值附近的离散决策 | Laghos `== 0.0` | 有：贪心 argmax；MoE 路由 top-k |
| 病态 / 弱可辨识 | McCullough–Vinod；不可复现的系统发育树 | 有：近似平局的 logit |
| 有偏累加 / 停滞 | FESOM 129 ZJ；爱国者导弹 | 有：BF16 权重导出吞掉 99.5% 的更新（Gao–Gao）；FP8 累加只有 14 位（DeepSeek-V3） |
| 两个不一致实现之间的反馈 | — | 有：RL 训推不一致 |
| 内核契约弱于算法的假设 | Zhang 2611.31030 | 有：批不变性、累加精度都是内核契约 |
| 平台变化暴露潜伏 bug | EC-Earth 3.1、Laghos | 有：cascade attention、Mamba 溢出 |

### 4.5 给导师的回答

**问题：一点点精度差距，是不是真的会造成非常大的影响？**

**回答：要分开看。“随机的、无偏的一点点舍入差”本身很少造成大影响；造成大影响的，是下面三种情形之一。**

1. **差距被离散决策放大，并且有反馈。**
   - 一个 0.01 的 logit 差，在最大两个 logit 近乎平局时就会翻转 token，之后整段输出不再合回来；
   - 在 RL 里，这又通过梯度回到模型。HPC 里对应的是 Laghos 的 `== 0.0` 分支和混沌系统。
   - 但平均分、集合统计量通常扛得住：LLM 评测的平均分基本不变，只有 1–19% 的单题翻转；气候集合检验接受 GPU 移植。
2. **差距是系统性的、有偏的，而不是随机的。**
   - BF16 权重导出吞掉更新（25 对种子，+6.1 分）；
   - BF16 FlashAttention 的舍入偏差导致 loss 爆炸；
   - FESOM 的盐分流失、爱国者导弹的截断。
   - 这类会单调累积，不会被平均掉。
3. **“差距”其实是 bug 或契约不一致，不是舍入。**
   - cascade attention 的 LSE 错误、Mamba 的 uint32 溢出、采样掩码不一致；
   - MoE 路由翻转（一个 token 偏 10–31 nats）；
   - 一边 FP32 一边 BF16；
   - 我们在迭代精化中发现的“报成功、答案错”。

**对 RL 训推不一致的直接回答**：
- 稠密模型、BF16、标准配方下，**没有可靠证据**表明良性舍入差显著影响最终结果。最好的反面证据是 slime 的 300 多次运行、Score Centering 和 CIS 的 3 个种子；正面证据大多是单种子，而且混有 bug 或训练端改动。
- MoE、低精度 rollout、采样语义不一致下，影响确实很大，证据充分。
- **领域最大的空白是因果证据**：没有任何研究每组至少用 5 个种子，只改 sampler 数值、其他全固定，来测效应大小。

**这对我们意味着什么**：
- 我们的价值不在于“消除一切舍入差”（逐位对齐已有很多人在做，代价是慢 9% 到 2.4 倍），而在于**区分良性舍入和真问题**：
  - 差值在证明过的界内，就是良性的，不必付对齐的代价；
  - 超出界，或者发生在离散决策点附近，就是要处理的。
- 现有的验收门槛都基于均值（k3 < 1e-3），已被证明看不到 10–31 nats 的尾部。HPC 里有害的案例也几乎都是“检查的东西和依赖的东西不一致”：
  - 用 B 级 GEMM 去做需要尺度协变的算法；
  - 9 步的集合检验看不到慢漂移；
  - 用不到 8 位有效数字的量去做 Dice 或 p 值判定。
- 我们迭代精化的结论（接受逻辑错了，舍入本身没错）正是第 3 类的 HPC 实例。

**可以做的实验**（直接回答导师的问题）：
- 设计：训练端与导出权重逐位相同，只改 sampler：(i) 逐位一致；(ii) 只关掉 sampler 的批不变性；(iii) 人为放大 3 倍、10 倍的扰动。再交叉“是否 IS 修正”和“稠密 vs MoE”，每格至少 8 个种子。
- 规模较大，需要多卡。我们现有的硬件（V100、5070 Ti）只能做小模型版本。

1. **“一点点精度差距”分两种，答案不同。**
   - 良性舍入：逐字输出不可复现，但平均分和标准 RL 训练基本不受影响。目前最好的反面证据（slime 300+ 次运行、Score Centering、CIS 3 个种子）都没看到显著差别。
   - 结构性差异和 bug：会造成大影响，证据充分。
2. **真正把小差距变大的，是“离散决策”加“反馈”。** 离散决策包括 argmax、路由 top-k、采样掩码、分支；反馈包括自回归生成和 RL 更新。证据显示，后果取决于差异发生在哪里（RoPE、路由），而不是平均有多大。
3. **领域里最大的空白是因果证据本身**：没有一项研究用足够的种子，只改 sampler 数值、其他全固定，去测效应大小。这是一个可以直接做的实验。
4. **对我们工作的含义**：
   - 现有的验收门槛（k3 < 1e-3、平均 exp|Δ| ≤ 1.05）基于均值，已被证明看不到 10–31 nats 的尾部；
   - “区分良性舍入和真 bug”正是精度契约能做的事：差值在证明的界内就是良性的，超出就是违约。这与我们在 HPC 迭代精化中的发现（报成功但答案错的，都是逻辑 bug，不是舍入）一脉相承。
